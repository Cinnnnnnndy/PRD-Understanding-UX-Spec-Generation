## §C 问题 → 目标状态映射（每条对应可验收的改进规格）

**问题1：枚举语义藏在 tooltip（🔴）**
- 目标：功能码改为**带标签的下拉/可搜索选择器**，选项显示「`0x06` 散热部件管理功能」，选中后旁边常驻显示标签；MS/RW 改为**带标签的二选一控件**（如分段按钮：`多读 / 单读`、`写 / 读`），底层仍存 0/1。语义从 hover→常驻可见。保留原始 hex 输入作为高级用户的备选输入路径。

**问题2：结果不可一键带走（🟡）**
- 目标：结果区 hex、dec 各加一个「复制」图标按钮，点按复制并显示 800ms「已复制 ✓」反馈（绿色 `#4caf50` 系，与文件已有 `#applyResult.success` 配色一致）。

**问题3：命令字结构无可视化（🟡 视觉层级 + 🟡 可用性）**
- 目标：结果区下方加一条 **32 格位布局条**，按真实位区间着色：功能码(31–26)、命令码(25–10)、MS(9)、RW(8)、参数(7–0) 各一色块，块宽按位数成比例。**严禁按十六进制字符等分**（字段不对齐 nibble）。悬停某字段输入框时高亮对应色块，反之亦然。

**问题4：三态混淆（🟡）**
- 目标：结果区三态分明——未输入/缺失字段 → 占位灰 `#8b8b8b` `0x--------`；合法（含零值）→ 强调蓝 `#4fc1ff`；仅在「字段超范围」时 → 错误红 `#f48771`，并在结果区下方点明哪个字段错。零值 `0x00000000` 用蓝（合法）而非红。

**问题5：可访问性偏小 + 色彩单一依赖（🟡）**
- 目标：错误/警告文案 ≥ 12px；非法字段除红色外加一个 `⚠` 图标前缀；`❓` 语义改为常驻标签后可移除，若保留则补 `aria-label` 且可 Tab 聚焦触发。

**问题6：装饰符号不统一（🟢）**
- 目标：统一为 VS Code 风格的左侧 3px `#4fc1ff` 竖条 section header，去除 🧮/⚡/◆ 混用（保留一个产品图标在主标题即可）。

## §D 跨视图一致性约束

本功能为**单视图**，无跨视图问题。统一约束：
- Section header：左侧 3px `#4fc1ff` 竖条 + 13px 半粗体，无多套 emoji。
- 输入框：背景 `#3c3c3c`，边框 `#6b6b6b`，focus border `#007fd4`，圆角 4px。
- 按钮层级：主(`#0e639c`) → 次(`#3a3d41`) → 文字按钮，颜色不得自创。
- 所有数值/代码用 monospace；内容在 VS Code 窄面板（≈ 320–700px）与宽屏都成立，**不假设宽屏两栏**。

## §E 各视图设计要求

### 计算器主面板
- 布局：单列优先，max-width 650px 居中（沿用现状，适配窄面板）；结果区置顶且最显眼。
- 字段区：命令码(16-bit) 单独一行满宽；功能码(语义下拉) 一行；MS/RW(二选一) + 参数 在一行平分。
- 位布局条：紧随结果数值下方，与字段输入双向高亮联动。
- 复制：结果区 hex/dec 旁各一个复制按钮。
- 空/零/错三态：按 §C 问题4 区分。
- 实现约束：**纯 HTML + CSS + JS 单文件**，沿用 `--vscode-*` 变量；保留 standalone polyfill；无构建、无新依赖。

## §F 状态覆盖要求（不能只设计 happy path）

| 状态 | 触发条件 | 视觉表现 |
|------|---------|---------|
| 初始/零态 | 页面首次打开（全默认 `00/0000/0/0/00`） | 结果 `0x00000000` 强调蓝（合法），位条全部按字段着色 |
| 未输入/缺失 | 某字段被清空 | 该字段占位灰，结果区 `0x--------` 灰，提示「请补全 [字段]」 |
| 计算（实时） | 字段变更 | 300ms 防抖后更新；过渡平滑不闪烁 |
| 字段超范围 | 单字段 > maxValue | 该字段红边框 + `⚠` 图标 + 字段下方「超出范围」；结果区红，点名出错字段 |
| 溢出 | 十进制 > 0xFFFFFFFF | 警告色 `#cca700`「将取低 32 位」，继续解析（沿用现状） |
| 复制成功 | 点复制 | 按钮短暂变「已复制 ✓」绿色 800ms |
| 应用 | 点「应用」且全合法 | 成功提示条（沿用 `#applyResult.success` 绿）；明确文案不要让人误以为只是写回十进制框 |
| 禁用 | 「应用」在有非法字段时 | 用灰禁用态（非红），避免与错误态混淆 |
