## 实体清单

这个功能没有持久化业务实体，唯一的「数据模型」是 **SMC 命令字（32-bit offset）** 及其 5 个位字段。

### 实体：SmcOffset（32 位命令字）

一个 `uint32`，按 MSB→LSB 切成 5 段。字段定义来自外部协议规格（不是从数字本身推导）：

| 字段 | 英文/代码名 | 位宽 | 位区间 | 取值范围 | 业务含义 |
|------|------------|------|--------|---------|---------|
| 功能码 | `function` | 6-bit | 31–26 | `0x00–0x3F` | 命令面向的部件域（见枚举） |
| 命令码 | `command` | 16-bit | 25–10 | `0x0000–0xFFFF` | 域内具体命令编号 |
| 读取方式 | `ms` | 1-bit | 9 | `0x0 / 0x1` | 0=多读，1=单读 |
| 读写方向 | `rw` | 1-bit | 8 | `0x0 / 0x1` | 0=写操作，1=读操作 |
| 参数 | `parameter` | 8-bit | 7–0 | `0x00–0xFF` | 设备编号或其他参数 |

> 位宽合计 6+16+1+1+8 = 32，正好填满一个 `uint32`，无空隙。字段边界**不在** nibble 边界上（功能码 6 位、命令码 16 位跨越半字节），所以肉眼按十六进制字符无法直接分段——这是本计算器存在的根本理由：替用户做位运算拆/合。

### 枚举映射：功能码 `function`（工程值 → 用户可读标签）

来源：`function` 字段 help-icon 的 `title` 文本。

| 工程值 | 用户标签 |
|--------|---------|
| `0x00` | 公共功能 |
| `0x01` | 扩展组件管理功能 |
| `0x02` | 机箱部件管理功能 |
| `0x03` | 计算部件管理功能 |
| `0x04` | 内存部件管理功能 |
| `0x05` | 存储部件管理功能 |
| `0x06` | 散热部件管理功能 |
| `0x07` | IO 扩展部件管理功能 |
| `0x08` | 加速扩展部件管理功能 |
| `0x09` | 供电部件管理功能 |
| `0x20` (32) | Reserved（保留） |
| `0x37–0x3F` (55–63) | OEM 功能 |

> ⚠️ 当前实现把这套映射**只塞在 tooltip 文本里**，校验逻辑只判断 `≤ 0x3F`，不区分「已定义/保留/OEM/未定义空洞」。`0x0A–0x1F`、`0x21–0x36` 是未定义空洞，用户填进去能通过校验但语义无效——这是工程化时应当显式建模的枚举表（见 `business-logic.md`）。

### 枚举映射：MS / RW（1-bit 语义位）

| 字段 | `0x0` | `0x1` |
|------|-------|-------|
| `ms`（读取方式） | 多读 | 单读 |
| `rw`（读写方向） | 写操作 | 读操作 |

> 这两个是典型「整数对用户无意义、必须在 UI 层映射」的位。当前 UI 只让用户填 `0`/`1`，**没有展示语义标签**——填的人得记住「1=单读、1=读」。

## 魔法值标注

| 值 | 出现位置 | 含义 | UI 处理要求 |
|----|---------|------|------------|
| `0xFFFFFFFF` (`MAX_U32`) | `parseDecimalOffset` 溢出判断 | 32 位上限；超过则按「取低 32 位」截断并告警 | 已有 `⚠️ 超过 32 位范围…将使用低 32 位` 警告，正确 |
| `0x20` / `0x37–0x3F` | 功能码语义 | Reserved / OEM 区段 | 当前**未**在 UI 区分，建议工程化时对保留/OEM/未定义区段给出不同提示 |
| 默认值 `00/0000/0/0/00` | 字段初值 | 合法的「全零命令字」`0x00000000` | 注意：初始态结果是**合法的** `0x00000000`，不是空态。空态与零值同形，需设计区分 |

## 实体关系图

```
SmcOffset (uint32, 0x00000000–0xFFFFFFFF)
├── function   (bits 31–26, 6b)  ── 枚举：部件域
├── command    (bits 25–10, 16b) ── 自由数值
├── ms         (bit 9,      1b)  ── 枚举：多读/单读
├── rw         (bit 8,      1b)  ── 枚举：写/读
└── parameter  (bits 7–0,   8b)  ── 设备编号/参数
```

- 没有跨实体引用；唯一关系是「整体 ↔ 5 个分量」的**双向编解码**。
- 编码方向：5 字段 → `encodeOffset` → 32 位值（实时，300ms 防抖）。
- 解码方向：十进制/十六进制偏移量 → `decodeOffset` → 回填 5 字段。

## 动态字段标注

无 CSR 动态语法、无表达式字段。所有字段都是定长十六进制字面量，无远程读取语义。
