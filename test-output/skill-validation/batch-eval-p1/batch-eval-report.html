核心概念：管道表达式语法
语法示例
$1;$2 |> expr($1 + $2) |> string.format("和: %.2f", $1) $1 |> string.upper($1) |> string.gsub($1, "A", "B") $1;$2 |> expr($1 > $2 ? $1 : $2)
1
输入声明段
$1;$2;$3 — 用分号分隔，定义 N 个位置参数，自动类型推导（数字/布尔/null/字符串）
2
管道运算符 |>
两侧必须有空格；前一阶段输出自动成为下一阶段第一参数
3
阶段函数
7 个内置函数：expr / string.format / string.cmp / string.sub / string.gsub / string.upper / string.lower；省略括号时等同 expr()
4
Lua 真值 + ?/: 三目
仅 null/undefined/false 为假，0 和 "" 均为真；?→and，:→or

内置函数一览

函数签名说明
exprexpr(expression)算术/逻辑表达式求值（SafeExpressionParser）
string.formatformat(fmt, ...)C-style printf 格式化
string.cmpcmp(a, b)字符串相等比较（去引号后）
string.subsub(s, start, end)Lua 风格子串（1-based，负数从末尾）
string.gsubgsub(s, pat, repl)Lua 模式替换 → JS RegExp
string.upperupper(s)转大写
string.lowerlower(s)转小写

使用场景分析
场景 01
固件配置值域验证
工程师在 BMC Studio 中设置寄存器字段值后，需要验证编码后的数值是否在合法区间。用管道表达式批量验证多组配置值，一次性看出哪些组合越界。
$1;$2 |> expr($1 << $2) |> expr($1 >= 0 and $1 <= 0xFFFF)
场景 02
字符串格式化回归测试
当修改了 string.format 或 gsub 逻辑后，需要确保历史用例的输出格式不变。粘贴测试用例集，一键批量回归，绿色全通才发布。
$1 |> string.gsub($1, "(%d+)", "[%1]") |> string.format("[%s]", $1)
场景 03
边界值/空值安全检测
测试当参数为 0、空字符串、null 时管道表达式是否能安全返回兜底值，而不是抛出异常（利用 Lua 真值特性做空值保护）。
$1 |> expr($1 or "默认值")
场景 04
数值转换链调试
多步数值转换（偏移计算 → 格式化 → 范围判断）时，需要看到每个管道阶段的中间值，快速定位哪一步出错。调试模式实时展示 intermediates。
$1 |> expr(($1 + 0x100) % 0x10000) |> string.format("0x%04X", $1) |> string.upper($1)

综合结论：痛点 → 洞察 → 设计策略

痛点 Pain

错误反馈断流 表达式出错仅 alert() 弹出，用户需 5 步才能恢复输入状态；每次错误都是一次完整的操作流中断
语言混用感 11 处英文字符串混入中文 UI，整体观感像未完成的内部 Demo，传递"草稿感"信号
主题适配断档 ~30 处硬编码颜色，暗主题（VS Code 默认）下颜色对比度失效，工具不像原生插件
隐藏功能无入口 模板变量通道和参数类型徽章均已实现逻辑/CSS，但用户完全无法感知和使用

洞察 Insight

开发者工具的留存核心是"节奏感" 任何打断输入节奏的交互（alert、焦点跳出、必须鼠标点击）都会显著降低工具的日活使用率
完成度信号影响信任度 语言混用、按钮样式不一致、未实现的预留功能会让用户感知到"这是个原型"，降低依赖意愿
主题一致性是"原生感"的最低门槛 VS Code 插件用户对主题适配有强烈期望，不适配暗主题等于在用户的主场环境里显得格格不入
功能可见性优先于功能完整性 模板变量功能逻辑已有，仅缺 UI 入口；补入口的成本远低于重写逻辑

设计策略 Strategy

策略 S1：Inline 优先 所有错误提示从 alert() 迁移至 inline 组件（输入框下方/行内）；延迟 debounce 300ms 触发，不阻断输入
策略 S2：键盘完备 绑定 Ctrl+Enter（应用）/ F5（执行批量）/ Tab（参数跳转）；确保全程零鼠标操作路径
策略 S3：Token 化全替换 系统替换所有硬编码颜色为 --vscode-* token；一次性解决亮/暗主题适配
策略 S4：打开功能入口 为模板变量添加折叠面板 UI；参数徽章改为动态渲染；中文化所有 UI 字符串
下一步：基于以上策略生成优化版 Demo → 选择设计系统后执行 Phase 2 · UX Spec 输出
P0 三项（F2 inline 校验 + C1 快捷键 + C5 模板变量面板）是 Sprint 1 最小可交付单元
