# 管道表达式批量评估器 · 产品文档

## 技术栈概览
纯 HTML + CSS + JS（无框架、无构建工具）。嵌入 VS Code WebView，使用 `--vscode-*` CSS 自定义属性保持视觉与宿主一致。核心引擎从 TypeScript 源 `sr-pipe-expression-evaluator.ts` 移植，含递归下降表达式解析器（SafeExpressionParser）+ 管道求值引擎（PipeEvaluator）。当前为 Beta 版本。

### A. 功能定义

一个嵌入 VS Code WebView 的**管道表达式调试与批量验证工具**，给 BMC 固件配置工程师用：

- **调试模式**：输入表达式 + 参数值 → 实时显示每个管道阶段的中间输出 → 查看最终结果 → 一键复制
- **用例模式**：粘贴文本格式的批量测试用例 → 一键批量执行 → 查看通过率统计 + 虚拟滚动明细 → 导出

核心功能清单：
1. 管道表达式解析（`$1;$2 |> expr(...) |> string.format(...) |> ...`）
2. 实时逐阶段求值（调试模式，每次输入变化立即重算）
3. 批量用例执行（用例模式，支持千级行虚拟滚动）
4. 结果归一化比较（match/mismatch/error 三态）
5. 结果导出至剪贴板

### B. 场景分析

**场景 1 — 即席调试**：工程师刚写完一条涉及位移和字符串格式化的管道表达式，不确定中间步骤的计算顺序。他打开批量评估器，在调试模式下填入两个典型参数值，逐步看到每个 `|>` 阶段的输出，确认第三阶段的 `string.format` 结果符合预期后，复制表达式投入使用。

**场景 2 — 批量回归验证**：工程师修改了一条已有的参数归一化表达式，担心破坏现有 20 条已知正确用例。他把用例粘贴到用例模式，点 Execute All，3 秒后看到 20/20 通过，放心提交改动。

**场景 3 — 学习探索**：新加入团队的工程师不熟悉 `string.sub` 的 Lua 风格（1-based，负索引）。他在调试模式下连续尝试几组不同的 start/end 值，直观理解了边界行为，无需查文档反复确认。

**场景 4 — 协作交接**：资深工程师把表达式 + 测试用例文本一起发给同事，对方粘贴进工具就能直接复现验证结果，无需口头解释。

### D. 核心流程

**调试模式主流程**（步骤顺序强依赖）：
1. 输入/修改表达式（必须先于填参数）
2. 点「应用表达式」→ 表达式解析 → 自动生成参数输入字段
3. 逐一填参数 → 每次输入触发实时计算 → 阶段输出即时更新
4. 确认最终结果 → 按需点「复制结果」

**用例模式主流程**：
1. （可选）切换前先设置好表达式
2. 粘贴用例文本 → 点「加载用例」
3. 点「Execute All」（批量执行）
4. 查看统计 + 虚拟滚动明细 → 按需导出

**顺序约束**：
- 切换模式会触发 `applyExpr()`，会清空已加载的 testCases —— 即**切换模式不清除表达式，但会清除用例数据**（⚠️ 当前实现：切换到调试再回来，用例消失）
- 应用新表达式也会清空用例数据（表达式变了，旧用例不再有意义）

### G. 注意事项洞察

1. **魔法 token 碰撞**：`__EMPTY_STRING__` / `__NULL__` / `__UNDEFINED__` 是内部协议字符串。若用户的测试用例数据中恰好包含这三个字符串作为值，会被误识别为特殊类型，产生静默错误。这是已知设计缺陷，需文档说明或改内部编码为不可打印字符。

2. **切换模式清空用例**：`applyExpr()` 被 `switchMode()` 间接调用（切换时不调用），但切换到调试模式再切回用例模式会导致 testCases 被清空（因为 applyExpr 在表达式改变时清空）。当前切换模式本身不调用 applyExpr，但用户如果在切换后「应用表达式」，用例就消失了。

3. **`executeBatch` 同步阻塞**：批量执行是在 `await setTimeout(0)` 后同步循环执行，对于大量（如 10000 条）用例会阻塞主线程。应分块执行或使用 Web Worker。

4. **`normOut` 仅去单层引号**：`replace(/^["']|["']$/g, '')` 只去首尾各一个引号字符，不处理嵌套引号。若期望值是 `"'hello'"` 这类嵌套格式，比较可能出现误判。

5. **参数徽章 SYNC 硬编码**：`badge-ref` / `badge-const` / `badge-literal` / `badge-template` 定义但从未使用，说明参数类型系统设计已完成、接入未完成——这是与宿主 postMessage 联调的主要技术债。
