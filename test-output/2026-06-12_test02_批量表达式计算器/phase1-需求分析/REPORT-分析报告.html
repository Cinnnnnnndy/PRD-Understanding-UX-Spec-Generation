陌生技术概念 · 四步法解释

管道表达式语法

① 输入声明
$1;$2 ← 分号分隔多个参数

② 管道阶段（必须两侧有空格）
|> expr($1 + $2)
|> string.format("%.2f", $1)

③ 模板变量（宿主注入）
${threshold} ← 替换为注入值

$N 作用域规则（关键！）

首阶段 $1/$2 → 原始输入值
后续阶段 $1 → 上一阶段输出（不是原始输入）
⚠ 易误解：第二阶段 $1 ≠ 原始第一个输入

支持的管道函数

函数示例说明
expr()expr($1 + $2)算术/逻辑/位运算；Lua 三元 ?:
string.formatstring.format("%.2f",$1)C 风格格式化
string.upper/lowerstring.upper($1)大小写转换
string.substring.sub($1,1,3)Lua 1 基截取
string.gsubstring.gsub($1,"a","b")Lua 模式替换 有 bug
string.cmpstring.cmp($1,"ok")字符串相等比较
⚠ Lua 三元语义特殊性
$1 > 0 ? "正" : "负" 中 ?→and :→or
0 和 "" 均为真值（与 JavaScript 不同！）

B · 场景分析〔承接 U·P〕

工程师在什么情境下使用这个工具

场景 1 新表达式开发调试
工程师写温度转换管道 $1 |> expr($1/100) |> string.format("%.1f°C",$1)，填入 ADC 值 2543，右侧实时显示阶段中间值。

原始 Demo 痛点：右侧空白无引导，新用户不知如何开始。
场景 3 模板变量独立调试
含 ${threshold} 的表达式在宿主外无法测试。

原始 Demo 不支持模板变量，必须临时改硬编码值，每次 3-5 分钟。
场景 2 批量回归验证
改了字符串替换表达式，粘贴 80 条 CSV 测试数据，执行全部，两秒内看结果。

原始 Demo 痛点：统计标签英文（Total/Matched），无法筛选「只看不匹配项」，需肉眼逐行找差异。
场景 4 历史表达式恢复
下午要改上午写过的格式化表达式。

原始 Demo 无历史记录，只能翻代码注释或重新从头写，约 5 分钟。

F · 竞品分析 + 专利潜力〔承接 T 趋势〕

行业对标与差异化

竞品/行业方案具备的能力差距（本工具的机会）
n8n / Apache NiFi 可视化管道 DAG，阶段中间值，批量执行 过重，需服务器，无法嵌入 VS Code Webview
regex101.com 即时反馈、阶段说明、历史记录 只限正则，不是通用管道，无批量测试
Postman 批量测试集、对比报告、历史 面向 HTTP，协议完全不同

专利潜力：中

差异化组合：
「Lua 风格管道表达式 × 阶段级中间值可视化 × Webview 嵌入 × 批量 CSV 测试」

单项能力各有先例，但四项组合针对 BMC/嵌入式领域 + VS Code 嵌入场景，业界未见完整先例。

交互角度专利描述

「用户在 IDE 嵌入面板内，通过逐阶段中间值可视化实时调试自定义管道表达式，并对任意规模的 CSV 测试集进行批量验证，无需离开 IDE 环境。」

G · 注意事项洞察〔汇合 B·P 约束面〕

设计红线与技术约束

技术约束（来自 B 维）

G1 · 单文件约束
CSS/JS 必须内联，零外部 CDN。所有优化方案必须保持零外链。
G5 · localStorage 多窗口共享
不同 VS Code 窗口共享同一 origin 的 localStorage。历史/设置 key 应加前缀区分实例。
G7 · postMessage 协议未统一
宿主侧键名需与工具侧保持一致（setTemplateVars vs TEMPLATE_VARS_UPDATE），否则注入失效。

踩坑风险（来自 P 维）

G2 · normOut 模糊比较
字符串 "7.00" 和数字 7.00 视为匹配。严格类型验证场景会误判。需在结果页面添加「比较规则」说明。
G3 · $N 参数上限歧义
参数 ≥10 时，$10 与 $1 正则冲突（replace 先匹配 $1）。UI 层应显示警告；工程上按索引降序替换修复。
G4 · executeBatch 同步阻塞
仅让出一帧（setTimeout(0)），1000+ 用例会阻塞主线程。大批次应分块执行或使用 Web Worker。
设计审查 · 原始 Demo

原始 Demo 存在的具体问题

严重（立即修复）
🔴 alert() 中断操作流
应用表达式失败时弹出浏览器 alert，强制打断操作，无法保留上下文。→ 改为 inline 错误提示
🔴 中英文混用
批量模式：「Execute All」「Export Results」「Showing X–Y of Z」等为英文，与其余中文界面割裂。
🔴 所有 badge 硬编码为 SYNC
每个参数都显示蓝色 SYNC badge，但实际参数类型不同。语义完全错误，误导用户。
🔴 string.gsub 量词 bug
%d+ 中的 + 被转义为 \+，量词失效。_luaPatToRegex 需修复 magic 集对量词的处理。
重要（优化提升）
🟡 右栏空白无引导
参数未填时右栏完全空白，新用户不知道接下来该做什么。→ 增加 3 张示例引导卡片
🟡 无历史记录 / 无模板变量
高频工作流的核心能力缺失。关掉工具后历史表达式全丢；含 ${VarName} 的表达式无法独立测试。
🟡 批量结果无筛选 / 无通过率
执行 100 条用例后，不匹配项分散在表格各处，需肉眼逐行扫描。无法一眼看出总体通过率。
⚪ 单栏布局 / 重视觉横幅
56px 蓝色横幅占据视口顶部，信息密度低。单栏布局需频繁上下滚动切换操作与反馈区域。
